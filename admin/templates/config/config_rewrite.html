伪静态基本设置

使用说明

什么是伪静态？ 把动态 URL（如 index.php?c=home&m=article&id=123）变成静态 URL（如 /article/123），更利于搜索引擎收录（SEO）且更美观。
使用步骤： ① 把顶部「伪静态功能开关」设为「开启」→ ② 在下方填写自定义 URL 规则 → ③ 保存后，在站点服务器（Nginx 或 Apache）中配置对应的重写规则（见页面底部说明）→ ④ 完成。
规则写法： 在规则中使用 {id}、{slug}、{year} 等占位符。保存后，前台页面的链接将自动按您填写的规则生成。

支持的占位符

📋 完整占位符速查：以下是系统支持的所有 URL 占位符，可任意组合使用。推荐使用 {slug} 或 {category_slug} 以获得更友好的 SEO URL。
占位符 含义 可用页面 示例规则
{id} 数字 ID 文章 / 分类 / 标签 / 页面 / 用户 article/{id} → /article/123
{post_id} / {article_id} 文章ID（同 {id}） 文章 news/{post_id} → /news/123
{slug} 别名 / 短名 文章 / 分类 / 页面 post/{slug}.html → /post/hello-world.html
{postname} 文章别名（同 {slug}） 文章 blog/{postname} → /blog/hello-world
{category_slug} / {cat_slug} / {category} 文章所属分类别名 文章 / 分类 {category_slug}/{slug} → /tech/hello-world
{tag_slug} / {tag} 标签别名 文章 / 标签 tag/{tag_slug} → /tag/php-basics
{name} 名称 分类 / 标签 / 用户 cat-{name} → /cat-PHP教程
{title} 文章标题（URL编码） 文章 / 页面 {title} → /我的第一篇文章
{category_name} 分类名称 文章 / 分类 category/{category_name} → /category/技术分享
{category_id} / {cat_id} 分类ID 文章 / 分类 cat/{category_id} → /cat/5
{tag_name} 标签名称 文章 / 标签 tag/{tag_name} → /tag/PHP
{tag_id} 标签ID 文章 / 标签 t/{tag_id} → /t/3
{author} / {nickname} 作者昵称 文章 / 用户 author/{author} → /author/小明
{username} / {author_slug} 用户名 文章 / 用户 u/{username} → /u/admin_xiaoming
{author_id} / {user_id} 作者/用户ID 文章 / 用户 user/{author_id} → /user/1
{year} 年份（4位） 文章 {year}/{slug} → /2026/hello-world
{month} / {monthnum} 月份 文章 {year}/{month}/{id} → /2026/06/123
{day} 日期（2位） 文章 {year}/{month}/{day}/{slug}
{hour} / {minute} / {second} 时/分/秒 文章 {year}/{month}/{day}/{hour}/{slug}
{page} 页码（可选） 任何列表页 category/{slug}/page/{page}
{views} / {view_count} 浏览量（较少用于URL） 文章 不推荐用于 URL 结构
📌 组合使用示例（推荐）：
文章: {category_slug}/{year}/{month}/{slug}.html → /tech/2026/06/hello-world.html
分类: category/{slug} → /category/technology
作者文章: author/{username}/{page} → /author/xiaoming/2
💡 提示： 没有占位符的规则（如 login、signin）是固定页面 URL。规则中 不包含 域名和 / 开头的前缀。多参数规则（如 {year}/{month}/{slug}）会自动将最后一个参数作为文章/分类/页面的标识符。

URL重写规则设置

服务器配置说明（重要）

⚠️ 保存 URL 规则后，必须同时在 Nginx 或 Apache 中添加相应的重写规则，否则自定义的 URL（如 /post/123.html）会出现 404 错误。
Nginx 配置（宝塔面板 / 军哥 LNMP / 自行部署）

在站点的 Nginx 配置中添加以下规则（通常是 server { ... } 块内的 location / 中）：

location / {
    try_files $uri $uri/ /index.php?$args;
}
如果使用宝塔面板，直接在「网站设置 → 伪静态」中粘贴上面规则即可
宝塔步骤：登录面板 → 左侧「网站」→ 找到您的站点 → 点击「设置」→ 左侧「伪静态」→ 粘贴上面的规则（即 try_files $uri $uri/ /index.php?$args;）→ 保存。
Apache 配置（phpStudy / XAMPP / WAMP）

在站点根目录的 .htaccess 文件中添加以下规则（通常系统已自动生成，若无则手动创建）：

<IfModule mod_rewrite.c>
    RewriteEngine On
    RewriteBase /

    # 如果请求的是已存在的文件或目录，直接返回
    RewriteCond %{REQUEST_FILENAME} -f [OR]
    RewriteCond %{REQUEST_FILENAME} -d
    RewriteRule ^ - [L]

    # 其他所有请求交给 index.php 处理
    RewriteRule ^(.*)$ index.php/$1 [L,QSA]
</IfModule>
Apache 常见问题排查
1. 确认 mod_rewrite 模块已启用（phpStudy：其他选项菜单 → Apache 模块 → 勾选 rewrite_module）
2. 确认 Apache 配置中 AllowOverride All（否则 .htaccess 不生效）
3. .htaccess 文件必须放在站点根目录（与 index.php 同级）
IIS / 其他环境

IIS 用户需要安装 URL Rewrite Module，然后在 web.config 中添加规则将所有请求重写到 index.php。如不确定如何配置，建议使用上面的 Nginx 或 Apache 方案。
